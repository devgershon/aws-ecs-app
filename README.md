# aws-ecs-app — Portfolio API on ECS Fargate

**Live:** http://portfolio-api-alb-1322983791.eu-west-2.elb.amazonaws.com &nbsp;·&nbsp; **Swagger UI:** http://portfolio-api-alb-1322983791.eu-west-2.elb.amazonaws.com/docs &nbsp;·&nbsp; **Author:** [devgershon](https://github.com/devgershon)

A FastAPI service running in a Docker container on AWS ECS Fargate. It sits in front of the [aws-serverless-api](https://github.com/devgershon/aws-serverless-api) and exposes the blog posts data through its own endpoints. The ALB gives it a stable public URL and handles health checks. GitHub Actions builds the image, pushes it to ECR, and triggers a rolling deploy on every push to main.

This is the third project in my AWS cloud engineering portfolio — the first time containers are involved. The [aws-static-site](https://github.com/devgershon/aws-static-site) handles the frontend, [aws-serverless-api](https://github.com/devgershon/aws-serverless-api) handles the data, and this service sits in the middle connecting them.

## Architecture

```
Internet
    |
    v
ALB (Application Load Balancer)
  - Stable public DNS
  - Health checks every 30 seconds
  - Rolling deploys with zero downtime
    |
    v
ECS Fargate (FastAPI container)
  - Docker image pulled from ECR
  - No servers to manage
  - Scales by task count, not by worker count
    |
    v
aws-serverless-api (Lambda + DynamoDB)
  - Blog posts fetched over HTTP
  - Service-to-service communication across two independent AWS systems

ECR stores the Docker images.
CloudWatch receives the container logs.
All infrastructure provisioned by Terraform.
Deployments automated by GitHub Actions.
```

## Deploy it yourself

You need an AWS account, AWS CLI, Terraform, and Docker installed.

### 1. Clone and configure

```bash
git clone https://github.com/devgershon/aws-ecs-app.git
cd aws-ecs-app
```

Open `terraform/variables.tf` and update `blog_api_url` to point at your own aws-serverless-api endpoint, and `allowed_origin` to your CloudFront URL from aws-static-site.

### 2. IAM permissions your user needs

Before running Terraform, your IAM user needs these policies. The cleanest approach is one custom policy covering everything rather than hitting the 10-policy-per-user quota:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "ecr:*", "ecs:*", "ec2:*",
        "elasticloadbalancing:*",
        "iam:*", "logs:*",
        "sts:GetCallerIdentity"
      ],
      "Resource": "*"
    }
  ]
}
```

Create this as a custom policy in IAM and attach it to your user.

### 3. Deploy the infrastructure

```bash
cd terraform
terraform init
terraform apply
```

This creates the VPC, subnets, security groups, ECR repository, ECS cluster, task definition, ECS service, ALB, and CloudWatch log groups. Takes about 3-4 minutes. When done:

```
alb_url                    = "http://your-alb-dns.eu-west-2.elb.amazonaws.com"
ecr_repository_url         = "YOUR_ACCOUNT.dkr.ecr.eu-west-2.amazonaws.com/portfolio-api"
ecs_cluster_name           = "portfolio-api-cluster"
ecs_service_name           = "portfolio-api-service"
ecs_task_definition_family = "portfolio-api"
```

### 4. Build and push the Docker image

**Important if you are on Apple Silicon (M1/M2/M3/M4):** Fargate runs on `linux/amd64`. You must build for that platform explicitly, otherwise ECS will pull an ARM image and fail to start it.

```bash
# Authenticate Docker with ECR
aws ecr get-login-password --region eu-west-2 | \
  docker login --username AWS --password-stdin \
  YOUR_ACCOUNT.dkr.ecr.eu-west-2.amazonaws.com

# Build for linux/amd64 and push directly to ECR
docker buildx build \
  --platform linux/amd64 \
  --provenance=false \
  -t YOUR_ACCOUNT.dkr.ecr.eu-west-2.amazonaws.com/portfolio-api:latest \
  --push \
  .
```

### 5. Force a new ECS deployment

```bash
aws ecs update-service \
  --cluster portfolio-api-cluster \
  --service portfolio-api-service \
  --force-new-deployment \
  --region eu-west-2
```

Wait 2-3 minutes, then visit the ALB URL.

### 6. Set up GitHub Actions

Add these secrets under `Settings -> Secrets -> Actions`:

| Secret | Value |
|---|---|
| `AWS_ACCESS_KEY_ID` | Your IAM access key |
| `AWS_SECRET_ACCESS_KEY` | Your IAM secret key |
| `ECS_CLUSTER_NAME` | From `terraform output ecs_cluster_name` |
| `ECS_SERVICE_NAME` | From `terraform output ecs_service_name` |
| `ECS_TASK_FAMILY` | From `terraform output ecs_task_definition_family` |
| `ALB_DNS_NAME` | ALB DNS name without `http://` |

Every push to main builds a new image, pushes it to ECR, and triggers a rolling deploy on ECS.

## Design decisions

**FastAPI over Flask.** FastAPI is async by default, generates Swagger UI automatically at `/docs`, and shows up in far more job descriptions than Flask for new roles. It was the right call for a portfolio project.

**Multi-stage Dockerfile.** The builder stage installs dependencies, the final stage copies only what is needed to run. No build tools in the production image, smaller and cleaner.

**Non-root user.** The container runs as `appuser` (UID 1001) rather than root. Standard practice — if something breaks out of the app layer, it cannot do much as a non-root user.

**One uvicorn worker per task.** Fargate tasks run with a single worker. To handle more traffic you increase `desired_count` in the task definition, not the worker count per container. Horizontal scaling, not vertical.

**Rolling deploy with zero downtime.** `minimum_healthy_percent = 100` means ECS never drops below the desired count during a deploy. New tasks start and pass the ALB health check before old ones are drained and stopped.

**`lifecycle ignore_changes` on task definition.** Terraform sets the initial task definition. The CI/CD pipeline updates it on every deploy using the commit SHA as the image tag. Without `ignore_changes`, running `terraform apply` after a deployment would revert the task definition back to the Terraform-defined image. This keeps Terraform and the pipeline from fighting each other.

## What I actually ran into

**An em dash in a Terraform string broke the security group.** AWS security group descriptions only accept ASCII characters. There was an em dash in the description field of one of the security groups and Terraform threw a validation error before even hitting AWS. Replaced with a regular hyphen and moved on.

**Built on Apple Silicon, Fargate runs on AMD64.** Docker on an M-series Mac builds ARM images by default. Fargate expects `linux/amd64`. The first few deployments kept failing with `image Manifest does not contain descriptor matching platform 'linux/amd64'`. The fix is to use `docker buildx build --platform linux/amd64 --provenance=false` which builds and pushes a clean single-architecture image rather than a multi-architecture manifest list that confuses ECS.

**The non-root user could not read the app files.** The container ran as `appuser` but the files were copied into the image without setting ownership, so the user had no read permission on `main.py`. The fix is one flag on the COPY instruction: `COPY --chown=appuser:appgroup app/ .`. Without it the container starts, uvicorn tries to import the app, hits a permission error, and exits with code 1.

**IAM policy quota.** AWS limits IAM users to 10 attached managed policies. After adding policies across three projects I hit the limit trying to attach the ECR policy. Solved by creating one custom policy covering everything Terraform needs across all projects and removing the individual managed policies.

## Cost

The ALB is the only resource here with a meaningful ongoing cost.

| Resource | Approximate cost |
|---|---|
| ALB | ~$0.008/hour (~$6/month minimum) |
| Fargate (256 CPU, 512 MB, 1 task) | ~$0.01/hour |
| ECR | $0.10/GB/month storage |
| CloudWatch Logs | First 5 GB/month free |

Run `terraform destroy` when you are done testing to avoid ongoing charges.
